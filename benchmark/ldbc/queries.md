  ---
  One important inconsistency to be aware of

  The benchmark timing functions (tq_*) and the validation functions (run_*) differ on knows traversal direction for X3, IC-5, IC-9, and A2:
```
  ┌──────────────────┬──────────────────────────────────────┬────────────────────────────────┐
  │      Query       │          Validation (run_*)          │        Benchmark (tq_*)        │
  ├──────────────────┼──────────────────────────────────────┼────────────────────────────────┤
  │ R2 / A2          │ forward + backward knows             │ forward only (colgroup cursor) │
  ├──────────────────┼──────────────────────────────────────┼────────────────────────────────┤
  │ X3 / IC-9 / IC-5 │ forward + backward knows for friends │ forward only                   │
  └──────────────────┴──────────────────────────────────────┴────────────────────────────────┘
```
  This is intentional in the FG benchmark — the tq_* functions are optimised paths that the columnar design enables (scanning the colgroup forward-only is the performance point being measured). The validation uses bidirectional traversal to confirm full correctness against NeuG which has both A→B and
  B→A edges loaded from the CSV.
